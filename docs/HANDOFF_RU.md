## Что реализовано

Выбор существующей папки игры, сохранение пути, обязательная проверка подписанного
манифеста перед запуском, обновление двух файлов, сохранение остальных параметров
INI, резервные копии, локальный откат и восстановление прерванного обновления.
Запуск и обновление защищены общей блокировкой каталога игры. Счётчик принятой
ревизии не уменьшается при работе нескольких экземпляров или локальном откате.
Во время работы окно не блокируется сетевой загрузкой. Сам EXE игры не меняется.

Политика ревизии 2 требует лаунчер не ниже 0.1.1. Подпись действует 90 дней;
администратор должен выпустить следующую ревизию до истечения. Общий откат —
новая ревизия с прежними исправными файлами, а не повтор старого манифеста.
Закрытый сервер доступа и авторизация в лаунчере не реализованы и не требуются
после выбора публичного распространения. Сайт не собирает аккаунты и пароли.

## Что осталось пользователю

1. Ручная проверка лаунчера и входа в BC2/Vietnam по TEST_RU.md.
2. Заменить A-запись сайта bc2.uplay2.ru на CNAME bc2 → rinatby.github.io.
   Запись master.bc2.uplay2.ru оставить на адресе действующего мастера.
   Пользователь отложил смену DNS. Пока bc2.uplay2.ru возвращает 87.249.43.129.
3. После обновления DNS дождаться сертификата GitHub Pages и включить Enforce HTTPS.
   CNAME уже привязан к репозиторию; Timeweb-сертификат для GitHub Pages не нужен.

До этого обновления лаунчера работают через резервный HTTPS-канал
raw.githubusercontent.com. Подпись и запрет старых ревизий проверяются так же;
ошибочная подпись основного канала не маскируется переходом на резервный.

## Приватные данные и следующий этап

Ключ подписи выпусков сохранён локально в `.secrets/release-signing.key`, исключён
из Git и архивов. Его необходимо сохранить отдельно и передавать администратору
приватно при смене машины выпуска. Восстановить его из публичного ключа невозможно.
Сертификат/ключ игрового мастера — другие файлы; они не менялись и не публиковались.

Перенос действующего мастера, его базы и статистики на VDS не выполнялся. Сначала
пользователь проверяет доменное подключение и тестовый лаунчер, затем знакомит
игроков с лаунчером. После этого можно планировать финальную остановку записи,
перенос свежей базы и переключение A-записи master.bc2.uplay2.ru.
