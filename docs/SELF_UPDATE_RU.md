# Самообновление BC2 Launcher

Схема и план согласованы пользователем 20.10.2026. После проверки установленной
версии пользователь выбрал ZIP без установки, кнопку скачивания на сайте и
помощь по ссылке в браузере. Реализация выполнена без дополнительных агентов.

## Установка и поведение

Основной вариант: `dist/local-0.2.2/BC2Launcher-0.2.2-portable.zip`. Распаковать
целиком в отдельную доступную для записи папку и запустить `BC2Launcher.exe`.
ZIP уже содержит проверенную исходную active-запись; самообновление работает
так же, как в установленном варианте. Регистрация приложения в Windows не нужна.
Путь к игре берётся из прежних пользовательских настроек, если он был сохранён.

Дополнительный установщик: `dist/local-0.2.2/BC2Launcher-Setup.exe`.
Установка для текущего пользователя, без запроса администратора, отдельно от игры.
Сборка рассчитана на x64-совместимую Windows 10/11.

```text
%LOCALAPPDATA%/Programs/BC2Launcher/
  BC2Launcher.exe       постоянный загрузчик 1.0.0, без Qt
  active.json           только schema и идентификатор версии
  versions/0.2.0/
    BC2Client.exe
    _internal/          Python, Qt, шрифты и фон
```

Ярлык ведёт на постоянный EXE. Новая версия приложения ставится в новую папку.
При запуске выполняется проверка подписанной описи и содержимого файлов.
Работающие EXE/DLL не перезаписываются обычным обновлением приложения.

Файлы игры, игровой EXE, база мастера, аккаунты и статистика не входят в этот пакет.
Выбранная папка игры остаётся в `%LOCALAPPDATA%/UPLAY2/BC2Launcher/settings.json`.
Копии `dinput8.dll`/`bfbc2.ini` остаются в `.bc2-launcher/backups` игры.
Удаление лаунчера не удаляет эти настройки или резервные копии игры.

При новой версии пакет загружается и проверяется в фоне. Затем появляется
«Обновить и перезапустить». Загрузчик открывает дескриптор именно старого процесса,
проверяет путь EXE и ждёт закрытия. Новый клиент подтверждает готовность через
индивидуальный наследуемый канал с nonce, PID и версией. Готовность подтверждается
после создания QApplication, ресурсов, окна и прохода event loop; сеть для этого не нужна.

Self-test ограничен 60 секундами, подтверждение нового окна — 30 секундами,
ожидание закрытия старого процесса — 60 секундами. Загрузчик не завершает процессы
по имени. При неудаче он завершает только своего нового ребёнка и один раз
запускает проверенную предыдущую версию. Незавершённая активация восстанавливается
по журналу. Потеря файла активной версии также допускает возврат к предыдущей.

Сбойный пакет не запускается автоматически по кругу; повторную попытку игрок
может запросить явно. Возврат программы не снижает принятую ревизию политики
и не снимает обязательное обновление перед игрой.

## Доверие и ограничения

Программа использует `updates/launcher-stable.json`; игровые файлы по-прежнему
используют `updates/stable.json`. Форматы разделены полями purpose/schema,
счётчики ревизий независимы. Повтор ревизии с другим payload не допускается.

Подписи — Ed25519, тот же существующий публичный ключ. Закрытый ключ используется
только локальным инструментом выпуска, в артефакты не попадает. Это не Authenticode:
сертификата издателя Windows у EXE/установщика пока нет.

HTTPS проверяет сертификат и каждый редирект. Разрешены только существующие
адреса сайта/GitHub. Пакет проверяется по размеру, SHA256, подписанной описи и
контрольным суммам каждого файла. Опись исключает чужие файлы и ссылки.

Лимиты: ZIP 512 МиБ, файл 512 МиБ, распакованное содержимое 1536 МиБ, 8192 файла,
опись 2 МиБ, политика 256 КиБ. ZIP64, шифрование и многотомные ZIP не поддерживаются.
Имена файлов внутри пакета ASCII; пользовательский путь установки может содержать
кириллицу и пробелы. Запрещены Windows device names, ADS, обход папок, повторы,
регистровые коллизии и reparse/symlink/junction.

Подготовленная папка связывается с точным хешем архива и подписанной описью
квитанцией staging в cache. Её сверяет и загрузчик. Одинаковая версия программы
не должна выпускаться с другим содержимым. Подписанный общий откат использует
новую ревизию, ссылающуюся на прежний исправный пакет.

При сетевой ошибке допустима только уже принятая, подписанная и ещё действующая
кэшированная политика программы. Неверная подпись не включает этот обход.
Это может задержать обнаружение нового требования при сетевой неисправности до
истечения кэша; политика игровых файлов проверяется отдельно перед запуском.
Просроченная политика не разрешает новые обновления или игру. Подписанная опись
уже установленного приложения без срока позволяет открыть интерфейс восстановления.
Недействительная начальная политика старого установщика не сбрасывает рабочую
установку; для игры в таком случае потребуется свежая политика из сети.

Загрузчик и его Python обновляются полным переносимым ZIP в отдельной папке либо
официальным установщиком. Требование нового загрузчика показывает ссылку на сайт;
обычный ZIP обновления приложения не меняет постоянный компонент.
Это не защита от другого вредоносного процесса с теми же правами пользователя,
который может заменить сам загрузчик и локальные данные.

## Сборка и автоматические проверки

В окружении community `.venv`: `tools/build.ps1 -Versioned -Version 0.2.0`.
Для второй версии: `tools/build.ps1 -Versioned -Version 0.2.1`.
Компилятор Inno Setup определяется в инструментах BC2masterServer либо передаётся
через `-InnoCompiler`. Подпись существующим локальным ключом обязательна; новый
ключ сборщик не генерирует. Build-версия фиксируется в подписанном ресурсе.

Сборщик прогоняет полный unittest, собирает клиент и загрузчик, проверяет оба
frozen self-test, формирует подписанный ZIP, начальную политику и Setup.
Действующая публичная политика игры не переподписывается сборкой.

В PowerShell с `PYTHONPATH=launcher`, `PYTHONUTF8=1`:

```powershell
& ./.venv/Scripts/python.exe -m unittest discover -s launcher/tests
& ./.venv/Scripts/python.exe tools/test_frozen_update.py --first dist/local-0.2.0 --second dist/local-0.2.1
& ./.venv/Scripts/python.exe tools/test_installer.py --first dist/local-0.2.0 --second dist/local-0.2.1
```

Runner-ы отказываются работать вне собственной новой папки `dist/selfupdate-e2e`.
Qt запускается offscreen, данные пользователя изолированы. Настоящая игра не запускается.
В smoke-режиме ошибка загрузки платформенного плагина Qt завершает тестовый
процесс без системного окна; обычный запуск этим правилом не изменяется.
Диагностика `--self-test-restart --smoke-startup` вызывает тот же метод передачи
перезапуска, что кнопка интерфейса, из установленного EXE старой версии.

Тестируются: реальные 0.2.0→0.2.1; PID/nonce readiness; отказ импорта Qt до
активации; потеря platform plugin после успешного import-only self-test;
возврат при удалении активного EXE; сохранение максимальной ревизии и bootstrap;
установка/переустановка/удаление в пути с кириллицей; сохранность реальных settings
и ярлыка. Сбои на границах журнала/указателя покрыты отдельными unit-тестами.

Подробные результаты сохраняются в `dist/selfupdate-e2e/<case>/report.json`.
Ручной вход в игру, совместимость чистой дисковой установки и Windows с отсутствующими
игровыми библиотеками этими проверками не доказываются. Итоговое ревью — авторское,
без независимого проверяющего по пожеланию пользователя работать одному.

## Публикация после ручной приёмки

1. Опубликовать Setup, неизменяемый подписанный app ZIP и SHA256 в существующем
   репозитории RinatBy/bc2-community. Локальные сломанные диагностические пакеты не публиковать.
2. Подписать `launcher-stable.json` новой ревизией с реальным URL артефакта и сроком.
   Инструмент: `tools/package_launcher.py policy`; повторять номер с новым payload нельзя.
3. Проверить публичные скачивания и подписи, затем добавить на сайт отдельную кнопку
   установщика. «Файлы проекта» оставить отдельной загрузкой.
4. Действующий минимум игры `0.1.1` повышать только после доступности и приёмки
   первого самообновляемого выпуска; старым 0.1.x нужен однократный установщик.

Помощь: `docs/FAQ_RU.md` — источник страницы `website/help.html`.
Кнопка «Помощь» в лаунчере открывает сайт в браузере; отдельного окна больше нет.
`tools/build_help.py --check` выполняется в проверке Pages. На главной рядом с
«Файлами проекта» добавлена контурная кнопка «Скачать лаунчер», ведущая на ZIP.
Регистрация пока внутри игры; вопросы Battlefield 3 в справку не включены.

Документация Inno Setup: [права текущего пользователя](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm),
[ISCC](https://jrsoftware.org/ishelp/topic_compilercmdline.htm).
